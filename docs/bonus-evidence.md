# B3-2 선택 보너스 진행 및 증빙

## 1. 이전 미션에 실제 적용

대상 저장소와 개선 내용 선정 진행 중. 실제 PR 링크와 AI 초안 대비 최종 수정 내역은 PR 생성 후 기록한다.

## 2. B3-1 문서 컨벤션

- 분석 대상: 로컬 `Codyssey-B3-1`의 최근 커밋 기록.
- 관찰: `docs: README 디렉터리 구조 추가`, `docs: 아키텍처 다이어그램 갱신`처럼 문서 변경에 `docs:` 접두사와 한국어 변경 설명 사용.
- 적용: `--convention b3-1-docs`를 선택하면 문서 변경에 대해 `docs:`로 시작하는 한국어 제목을 프롬프트에 요청한다. 기본값은 컨벤션 미적용.
- 확인: `python3 -m unittest discover -s tests -v`로 옵션 적용 전 프롬프트에는 추가 지시가 없고 적용 후에는 지시가 존재함을 확인했다.
- 실제 AI 생성 결과 비교: 동일한 가상 README 변경을 사용해 적용 전·후 각각 한 번 호출했다.
  - 적용 전: `docs: README에 설치 방법과 실행 예시 추가` (입력 241, 출력 23토큰; 형식 오류 `[]`)
  - 적용 후: `docs: README에 설치 방법과 실행 예시 추가` (입력 294, 출력 23토큰; 형식 오류 `[]`)
- 관찰: 적용 전에도 모델이 같은 접두사와 한국어 형식을 선택하여 두 결과가 같았다. 이 사례에서 실제 출력의 변화는 관찰되지 않았으며 옵션은 형식을 프롬프트에 지시한다.

## 3. 안전 모드 고도화

- 기본 마스킹: 이메일, `api_key`/`token`/`secret` 형태의 일부 할당값을 가린다. 모든 비밀정보를 탐지하지는 못한다.
- 선택적 전송 제한: `--safe-mode --safe-max-diff-lines 200`은 스테이징 전·후 diff를 각각 최대 200줄로 제한하고 초과 시 `[나머지 diff 생략]`을 붙인다. 줄 수는 1 이상의 정수로 조정 가능하다.
- 확인: 위 테스트에서 각 diff의 1줄만 남고 초과 문장이 생략되며 원본이 유지되는 것을 확인했다. 기존 가짜 이메일의 안전 모드 OFF/ON 비교는 각각 원문 포함/마스킹 표시로 확인했다.
- 새 파일 본문과 Git 상태는 diff 줄 제한에 포함되지 않는다. 새 파일 본문은 별도의 파일당 1,200자·전체 6,000자 제한을 받는다.
